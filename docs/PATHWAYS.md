# Where q1729 is going

q1729 can grow into a research platform. Today it has an archived GPU case study
and graph construction; a general experiment engine and new scientific claim
still need evidence. The [README](../README.md) defines the research thread and
the [roadmap](roadmap.md) defines execution order. This page explains that choice.

| Horizon | Concrete outcome | Question answered |
| --- | --- | --- |
| Now | Repair validation/provenance and repeat a bounded π study | Can someone trust and reproduce the measurements? |
| Next | Build a specified classical code and compare validated decoders | What useful question can the graphs answer? |
| Then | Run a feasible qLDPC construction/decoding study | Does the mathematical thread support a quantum-code experiment? |
| When justified | Focused paper and shared experiment machinery | Is there a contribution to publish and a pattern to reuse? |
| Longer term | Independent reproduction, portability and shared analysis | Can others conduct research with these tools? |

The π experiment is an educational simulator case study: QAE encodes a known
amplitude and does not establish quantum advantage. Profile before explaining
timing causes. Classical decoding is the bridge to qLDPC: validate a matrix
and reference decoder before accelerating, then choose a quantum construction
that fits the budget. A naive full graph self product is too large to store densely.

A paper can precede the platform. Its gate is a narrow contribution, related
work, fair controls, reproducible evidence and critical review. Novelty and
arXiv acceptance remain unverified. If the study reproduces known behavior,
publish an honest technical report and refine the question.

The next code milestone is **[P1-R1](roadmap.md#p1-r1--protect-and-validate-evidence)**.
Literature review and Phase 2 protocol design can proceed alongside repairs.
Cloud hardware, ROCm and a website remain conditional later work.
